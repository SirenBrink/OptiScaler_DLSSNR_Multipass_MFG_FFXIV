# OptiScaler FFXIV HDR10 test — 2026-09-26

Implemented an opt-in SDR-to-HDR expansion path owned by OptiScaler. This is not native scene-linear HDR reconstruction and cannot recover game-clipped highlights. No RenoDX code is imported. Shader implements sRGB decoding, highlight expansion above linear 0.5, BT.709-to-BT.2020 conversion and ST.2084 PQ encoding. Working scene/NR input remains SDR.

Controls: OptiFG -> FFXIV HDR10 output (experimental). Restart enable. Peak 1100 nits, paper white 203 nits, expansion 0.5. Expansion zero maps SDR white to paper white; one maps white to peak. Exact black survives 10-bit quantization. HUD and scene share the curve in this first test; independent HUD luminance is not implemented. The existing OptiScaler overlay draws after conversion and needs visual HDR validation.

Only FFXIV's DX11/DX12 presentation bridge and DLSS-G or FG-off are targeted. Native DX11 without the bridge is unsupported. Windows HDR is checked on the output before requesting RGB10 output; SDR remains the path otherwise. Disable RTX HDR/Auto HDR for HDR testing. Existing ForceHDR is not used. XeFG/FSR FG cannot be selected while this HDR path is active. Enable only with DLSS-G or no FG selected at startup.

The game-facing swapchain stays SDR. The visible DX12 swapchain is RGB10/PQ, including resize. Final and HUD-less images share one conversion. HUD-less is converted and tagged OnlyValidNow during the capture recording, not revisited on a potentially closed command list at Present. Separate SDR UI tags are rejected; existing final/HUD-less difference handling remains. Depth/motion and native NR exposure interpretation are unchanged.

Each conversion owns descriptors, source and output until its command recording is reset/destroyed AND GPU completion is observed. A bounded pool refuses unsafe reuse. Ownership is deliberately retained across process shutdown if still referenced. CPU conversion never waits for GPU readback. GPU conversion uses typed RGB10 UAV storage (checked on creation), then copies to the presentation buffer.

Tests: compiled HLSL on D3D11 WARP with RGB10 UAV, black/white/neutral ramp and primaries at expansion 0/0.5/1; production DX12 converter on WARP with 40 fenced reuse cycles; existing GPU-lifetime regressions. Release x64 build. These do not confirm physical HDR display behavior or NVIDIA DLSS-G runtime acceptance. User testing remains essential: HDR off/on across restart, NR off/on, FG off/on, multiplier changes, resize and shutdown.

Known first-test limitations: SDR expansion only, shared HUD curve, no HDR10 mastering metadata hints yet, no automatic display peak calibration, and no HDR support on alternate FG backends. Runtime negotiation/conversion errors are logged; initial unsupported-display request stays SDR. Runtime conversion failure does not silently present SDR pixels as PQ.
